# MARAT DETAILING

Сайт детейлинг-студии в Астане. Полностью переработанная страница на HTML, CSS и JavaScript, без клиентского фреймворка. RU/ҚАЗ, мобильная навигация, реальные публикации Instagram, консультация в WhatsApp и Google-карта с точкой студии.

## Запуск и проверки

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:4173. Нужен Node.js 22 или новее. Сайт можно открыть и напрямую через index.html; локальный сервер удобнее для проверки.

```sh
npm test
npm run test:browser
npm run build
```

Браузерные тесты используют установленный Google Chrome. Они проверяют загрузку изображений, доступность через axe, мобильное меню, оба языка, сохранение языка, переход формы WhatsApp и отсутствие горизонтального скролла на ширинах 320–1920 px. Тест формы перехватывает переход: настоящее сообщение никому не отправляется.

## WhatsApp

Для перехода в консультацию используется официальный формат `https://wa.me/77078582519?text=...`. Кнопка услуги добавляет её название. Форма добавляет имя, модель, услугу, необязательный телефон и пожелания.

Обязательные поля: имя, автомобиль и согласие на передачу данных. После нажатия открывается WhatsApp с готовым текстом. Клиент проверяет и отправляет его сам. Сайт не сохраняет заявки в базе данных. WhatsApp Business Cloud API не нужен для этого сценария: он нужен для серверной автоматизации отправки сообщений, которой здесь нет.

Без JavaScript остаются прямые контакты; форма предлагает перейти в WhatsApp напрямую. Меню, поля и ссылки имеют видимые состояния фокуса, FAQ работает на нативном `details`.

## Google Maps

Карта без ключа работает через iframe с подтверждёнными координатами, а маршрут через [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started). Ключ для маршрута не требуется.

Код поддерживает [Google Maps Embed API](https://developers.google.com/maps/documentation/embed/embedding-map). Для этого:

1. В своём Google Cloud проекте включите **Maps Embed API** и получите браузерный ключ.
2. Ограничьте ключ этим API и HTTP referrers вашего сайта (`https://marat-detailing.vercel.app/*`, а для локальной проверки при необходимости `http://127.0.0.1:4173/*`).
3. В `config.js` заполните `googleMaps.apiKey`. Это публичный браузерный ключ; серверные ключи сюда не помещать.
4. Необязательное поле `placeId` используйте только с проверенным Google Place ID студии. Без него точка задаётся координатами.

При непустом ключе сайт автоматически использует `/maps/embed/v1/place`. Пока ключ не предоставлен, официальный Embed API не активирован; работает вариант карты без ключа. Блок не создаёт карточку бизнеса в Google Business Profile: это отдельная процедура владельца.

## Изображения и шрифты

Фото приветствия `marat-enhanced.webp` улучшено из снимка, предоставленного владельцем. Исходник сохранён в `marat-reference.png`. Это AI-восстановление низкого разрешения, поэтому мелкие детали могут отличаться от оригинала.

`work-bmw.webp` и `work-getz.webp` получены из реальных публикаций студии и ссылаются на соответствующие Reels. Hyundai показан как начало подготовки, а не вымышленный готовый результат.

Обложка Porsche и иллюстрации услуг созданы встроенным ImageGen. Это художественные иллюстрации, не заявленные клиентские проекты. Точные промпты и происхождение перечислены в `design/ASSETS.md`. Шесть отдельных референсов разделов сохранены в `design/references/`; их нельзя считать фотографиями настоящей студии или Марата.

Оптимизация локальных исходников:

```sh
node scripts/optimize-images.cjs
```

Шрифты загружаются локально, без обращения к Google Fonts. Лицензия Manrope приложена рядом с файлами.

## Публикация

```sh
npm run build
```

Опубликуйте содержимое `dist/`. В него попадают только файлы сайта, WebP, шрифты и favicon. Тесты, инструменты, дизайн-референсы и исходные фотографии туда не копируются. `vercel.json` настраивает команду сборки, `dist` и защитные заголовки. Сайт совместим и с другим статическим хостингом.

Канонический домен сейчас `https://marat-detailing.vercel.app/`. При смене домена обновите canonical, Open Graph, Schema.org, robots.txt и sitemap.xml. После замены номера или адреса в config.js обновите также HTML-контакты и Schema.org, чтобы данные оставались корректными без JavaScript и для поисковых роботов.

Изменения в production появляются после публикации или слияния в настроенную production-ветку Vercel. Локальное сохранение файлов само по себе production не обновляет.
